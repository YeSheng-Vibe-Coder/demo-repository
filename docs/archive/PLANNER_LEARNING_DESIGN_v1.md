# Planner 自适应调查与经验改进设计

状态：部分实施，当前主线以 [实现对照](IMPLEMENTATION_ALIGNMENT_AUDIT.md) 为准。案件 LLM 审批已移除；评审属于规则更新阶段。定向样例仅为实验分支，不默认推广。

## 运行职责

Planner 根据当前证据自主提出假设、选择动作、观察结果、继续或 Replan、结束调查。工具不编码固定业务顺序。执行器只约束权限、参数、时间范围、证据引用、预算与重复执行，不替 Planner 决定调查结论。新增数据聚合工具负责提供可验证的事实，不承担主观推理。

独立 Rule Evaluator 评审当前规则与候选规则的逻辑、差异、来源、适配性和回放效果。调查样本由独立程序逐笔校验标签；案件结论诊断不属于业务主线审批。模型自评分不能替代独立标签与规则指标。

当前显式 thinking 配置关闭；这不等于模型没有规划能力，也不能称为已验证的深度推理方案。启用推理模式应做同样本、同总 Token 上限的独立对照，比较证据判断、恢复率和用量，再决定是否使用。

## 经验改进闭环

`开发集调查轨迹 → 独立评分 → 失败归因 → 候选策略版本 → 固定验证集对照 → 接受或拒绝 → 版本化发布/回滚`

1. **轨迹库**：保存模型/提示/工具/策略/数据版本、各步可观察状态、动作、Observation、覆盖与成本、最终结论。秘密和隐藏推理不作为学习材料。
2. **结果与奖励**：保留多维指标，包括独立真值效果、证据引用正确性、范围误判、合理弃答、无效重复、SQL/Token 成本。不要只奖励少查询或命中可疑标签；单笔正标签不保证局部窗口足以构成可解释的网络证据。
3. **经验提炼**：从开发轨迹提炼可迁移经验与反例，例如“完整单笔查询可以回答本窗口笔数，但不能证明源账户无其他交易”。不保存“某个账户是洗钱”的捷径供 Planner 检索。
4. **按需检索**：H-MEM 可存储经验；需补充业务情境索引、适用范围、来源版本和质量门槛。经验是参考，不能覆盖本案事实。
5. **策略优化器**：产生候选 Prompt、经验选择、工具描述与规划示例；每项变更有版本与来源。工具权限、发布门禁、测试集和预算上限不属于它可自动修改的范围。
6. **验证 Harness 与版本注册**：在固定验证集按同预算对比候选与现用策略，通过才发布实验版本。反复使用验证集会产生适应性过拟合，须限制候选次数并保留最终测试集；测试结果不能回流调参。

## 数据边界

学习使用 development；validation 用于候选选择；test 保留最终评估。按时间划分，经验与特征按 as_of 截断。标签仅供独立离线评分，不进入当前案件的模型输入。开发数据提炼的通用策略可冻结后用于后续时间分区；案件专属记忆不能跨分区泄漏。已知账户重叠不能当作新账户泛化成绩，需额外评估新账户/网络隔离场景。

旧轨迹回放可检查合同和已知错误，不能证明一个选择了新动作的策略效果；新查询要重新在冻结数据视图中执行。

## 与真正强化学习的区别

上述流程改进的是策略配置和可检索经验，不改变基础模型权重。真正 RL 还需要：可重置的调查环境、可信 verifier/reward、足够多样的 rollouts、可训练模型权重、训练基础设施和独立评估。NVIDIA NeMo Gym 可提供环境与验证框架，训练仍需配套训练框架和算力。当前免费推理 API 的可用性不能推导出训练权限或免费训练额度。

参考：[NeMo Gym Training](https://docs.nvidia.com/nemo/gym/v0.6.0/about/concepts/training/)、[Meterless Engines](https://github.com/Meterless/Meterless)。
